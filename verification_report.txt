rclone-multithreaded-upload v0.0.19 verification report
Date: 2026-07-07

SCOPE
-----
v0.0.19 replaces repeated remote cleanup/reservation listings with a per-remote
three-snapshot planner while preserving the configured clean -> reserve -> upload
-> clean -> final verification workflow.

NORMAL SUCCESSFUL REMOTE SNAPSHOT TARGET
----------------------------------------
1. PRE-UPLOAD recursive rclone lsjson
   Used in memory for:
   - age cleanup planning
   - max_files planning
   - max_size planning
   - max_total_size upload reservation planning

2. POST-UPLOAD recursive rclone lsjson
   Used in memory for:
   - age cleanup planning
   - max_files planning
   - max_size planning
   - max_total_size cleanup planning

3. FINAL recursive rclone lsjson
   Used in memory for:
   - all max_files verification
   - all max_size verification
   - max_total_size verification

This is three recursive remote listing commands, not three total rclone commands.
Actual delete, upload, optional trash cleanup, and backend detection commands remain
when required. Provider API pagination can also occur inside a recursive listing.

BEHAVIOR PRESERVED
------------------
- Oldest-first deletion ordering.
- Complete-file deletion; files are not partially selected.
- Reservation selects until selected bytes are at least the exact calculated deficit.
- 1 MiB reservation safety headroom.
- One-byte transfer-cap allowance.
- --cutoff-mode CAUTIOUS.
- copy, sync, and move upload command support.
- Backend-specific hard-delete options for Drive, MEGA, and OneDrive.
- Independent per-remote pipelines with no global snapshot/reservation barrier.
- Post-upload cleanup after failed or partially transferred uploads.
- Final live verification.
- Per-remote stage/error retention and FINAL RUN RESULT.

BEHAVIOR OPTIMIZED
------------------
- Removed standalone rclone delete --min-age remote traversal.
- Age deletion is planned from snapshot ModTime values.
- Removed individual cleanup-target lsjson calls.
- Removed separate remote-quota lsjson calls.
- Removed repeated reservation cleanup passes and their local/remote re-reads.
- Added mutable working snapshots; planned deletions are removed from the in-memory
  working state immediately so subsequent rules see simulated post-delete state.
- Added one combined RemoteDeletePlan per remote snapshot cleanup phase.
- Added concurrent single-flight local rclone size caching keyed by normalized local
  path plus source-selection filters.
- Combined post-upload cleanup rule and max_total_size planning into one snapshot.
- Combined all final rule/quota verification into one final snapshot per remote.

REAL CLOUD LIMITATION
---------------------
No destructive test was run against the user's real GDrive, MEGA, or OneDrive
remotes. The test environment validates application planning, command flow,
concurrency, delete-list behavior, upload state mutation, cleanup, and verification.
It cannot reproduce provider-side pagination timing, throttling, trash semantics,
crypt/backend behavior, or concurrent external changes to a live remote.

v0.0.19 intentionally reduces live re-reading. A live remote can change after a
snapshot is read. The remaining safety layers are the 1 MiB reservation headroom,
reserved upload transfer cap, post-upload live snapshot/cleanup, and final live
snapshot verification. These reduce risk but do not eliminate destructive-operation
risk.
