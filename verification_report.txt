rclone-multithreaded-upload v0.0.21 verification report
Date: 2026-09-07

SCOPE
-----
This release improves only the command-line parser, built-in CLI documentation,
and regression coverage. Upload, cleanup, reservation, deletion, stage-barrier,
threading, and safety behavior are unchanged from v0.0.20.

CLI HELP BEHAVIOR
-----------------
The executable now documents every supported user-facing flag in --help:

- -h / --help
  Prints the complete CLI help, including every flag, explanation, examples,
  and the usage line, then exits.

- -c PATH / --config PATH
  Selects the JSON configuration file. Required for normal runs and for
  --validate-config.

- --validate-config
  Loads and validates the config, prints the effective startup summary, then
  exits without lock creation or rclone execution.

- --version
  Prints the application version and exits without requiring a config file.

INVALID CLI INPUT
-----------------
FullHelpArgumentParser overrides argparse's normal terse error path.

Any CLI parsing error now:
1. prints the complete help/options text;
2. prints the specific argparse error;
3. exits with argparse status 2.

Verified examples include:
- unknown/misspelled option: --wrong-flag;
- missing required -c/--config.

The normal --help and --version paths still exit successfully without requiring
a configuration file.

SAFETY / RUNTIME BEHAVIOR
-------------------------
No upload/cleanup runtime logic was changed in v0.0.21. The v0.0.20 global stage
barriers, failure isolation, prerequisite skips, three-snapshot planner,
oldest-first whole-file deletion, reservation headroom, transfer cap, backend
hard-delete handling, post-upload cleanup, and final verification behavior remain
unchanged.

NOT FULLY TESTED
----------------
No destructive test was run against real Google Drive, MEGA, OneDrive, crypt
wrappers, or other live cloud remotes. Provider pagination, rate limiting,
throttling, trash semantics, permissions, network interruptions, concurrent live
remote changes, and real long-running transfers therefore remain outside the
local automated test environment.
