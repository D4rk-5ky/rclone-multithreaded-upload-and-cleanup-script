rclone-multithreaded-upload v0.0.25 verification report
Date: 2026-09-11

SCOPE
-----
This release adds a friendly config-level script/job name and optional final-run
MQTT JSON result publication intended for Home Assistant automation. It preserves
the v0.0.24 strict newest-to-oldest quota cutoff policy, complete-file uploads,
hard-delete versus trash-mode distinctions, stage barriers, and post-upload
cleanup/final verification behavior.

SCRIPT / JOB NAME
-----------------
A new optional root `script_name` identifies the configured cron/job instance.
The default is `rclone-multithreaded-upload`. The configured value is printed in
STARTUP SUMMARY and FINAL RUN RESULT and is included in MQTT JSON as
`script_name`.

Existing per-destination `upload_directories[].name` values are unchanged and
remain the friendly names for individual remotes such as GDrive, Mega, or
OneDrive. MQTT reports these separately in the `remotes` array and
`failed_remotes` list.

MQTT FINAL RESULT
-----------------
MQTT is optional and disabled by default. Enabling it requires an MQTT broker
host and the optional paho-mqtt Python dependency. The dependency is imported
only when MQTT publishing is enabled.

The final payload is schema-versioned and contains:
- schema_version and event name;
- script_name and application/application_version;
- UTC timestamp;
- overall status (`success` or `failure`) and boolean success;
- process exit_code;
- null error on success or combined captured stage error text on failure;
- friendly failed_remotes;
- one structured item per remote with name, remote_path, overall remote status,
  reservation/upload/post_cleanup/final_quota stage states, and structured
  stage errors.

MQTT configuration supports host, port, topic, username/password, client ID,
QoS 0/1/2, retain, keepalive, TLS, optional CA file, TLS-insecure override, and
publish timeout. Publish topics are validated as concrete topic names and reject
`+`/`#` subscription wildcards. Password values are never printed in startup
summaries.

The publisher starts the paho network loop, waits for the broker connection to
be established, publishes the JSON, and waits for publication completion before
disconnecting. Default QoS is 1 and default retain is false.

MQTT TRANSPORT FAILURE POLICY
-----------------------------
MQTT is notification-only. If the upload/cleanup run has already completed and
the broker is unavailable, paho-mqtt is missing, authentication fails, or the
publish times out, the MQTT error is printed but the script's already-computed
rclone/cleanup result and process exit code are not rewritten.

A config-load failure cannot publish because a valid broker configuration has
not been established. `--validate-config` never publishes. This release targets
normal completed runs that reach FINAL RUN RESULT.

HOME ASSISTANT EXAMPLE
----------------------
`home-assistant-mqtt-automation.example.yaml` subscribes to the example topic
`homeassistant/rclone-upload/result` and uses `trigger.payload_json`.

The automation:
- reads `script_name`, `status`, `error`, `failed_remotes`, and remote names;
- branches explicitly on `success` versus `failure`;
- sends a Pushover notification and a `persistent_notification.create` action
  for both success and failure;
- includes the configured script name prominently in the notification title;
- includes friendly remote names on success;
- includes failed remote names plus captured error text on failure;
- creates a persistent warning if an unexpected status is received.

The Pushover action is intentionally named `notify.pushover` as an example and
must be changed if the user's Home Assistant Pushover notify entity/action has a
different name.

OPTIONAL DEPENDENCY
-------------------
`requirements-mqtt.txt` contains:

    paho-mqtt>=2.0,<3

The runtime code is compatible with the Paho 2.x callback API and has a fallback
constructor path for clients without CallbackAPIVersion. The automated suite
explicitly tests the Paho 2.x VERSION2 constructor path.

PRESERVED V0.0.24 QUOTA BEHAVIOR
--------------------------------
Quota-managed file selection remains a strict contiguous newest-first prefix:
- inspect eligible files newest to oldest;
- select the next complete file only when it fits;
- stop immediately at the first file that does not fit;
- do not search older files for a smaller gap-filling candidate;
- zero selected files is a successful upload no-op;
- quota-managed transfers use frozen NUL-delimited --files-from0 lists;
- no runtime --max-transfer or --cutoff-mode is used.

Remote cleanup still frees complete remote files according to the existing
oldest-first planner when reservation space is required. Hard/direct delete and
trash/backend-default delete remain distinct, and existing empty_trash activity
safeguards are preserved.

NOT FULLY TESTED
----------------
No destructive test was run against real Google Drive, MEGA, OneDrive, crypt
wrappers, or other live cloud remotes. No live MQTT broker or live Home
Assistant instance was available in the local test container, and paho-mqtt
could not be installed there because the container has no Internet access.
MQTT behavior was tested with deterministic fake clients plus current Paho API
documentation review. Home Assistant YAML was syntax/structure parsed and its
MQTT JSON trigger, persistent-notification action, and Pushover action patterns
were checked against current Home Assistant documentation.

Provider-specific trash behavior, pagination, throttling/rate limits,
permissions, network interruptions, concurrent live remote changes, broker
ACL/TLS configuration, and real long-running transfers remain outside the local
automated test environment.
