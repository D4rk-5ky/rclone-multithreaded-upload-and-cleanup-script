rclone-multithreaded-upload v0.0.26 verification report
Date: 2026-09-16

SCOPE
-----
This release fixes final MQTT result publishing when the installed Paho MQTT
client uses legacy loop_start() return behavior. No cleanup, reservation,
upload, quota, delete-mode, locking, or final-verification algorithm was
intentionally changed.

MQTT LOOP_START COMPATIBILITY FIX
---------------------------------
The v0.0.25 publisher required client.loop_start() to return MQTT_ERR_SUCCESS
(0). Some valid Paho implementations instead return None after successfully
starting the network loop. That caused an otherwise successful completed run to
log:

    MQTT network loop returned error code None

v0.0.26 accepts both successful conventions:
- None, used by legacy Paho behavior;
- MQTT_ERR_SUCCESS / 0, used by newer behavior.

Explicit non-success/error return codes are still rejected. After the network
loop starts, the publisher continues to wait for broker connection, publish the
configured JSON payload, wait for publication completion, disconnect, and stop
the loop.

MQTT FAILURE POLICY
-------------------
MQTT remains notification-only. A broker/authentication/network/publish failure
is reported but does not rewrite the already-computed backup/cleanup result or
process exit code.
