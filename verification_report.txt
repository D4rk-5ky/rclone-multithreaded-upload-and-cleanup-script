Behavior boundaries preserved / checked
---------------------------------------
- Shared RuntimeState values are read through STATE at call time to avoid stale
  imported scalar and Path values after load_config().
- One recursive remote-root lsjson listing is used for managed max_total_size
  accounting, with cleanup-rule filtering and relative-path deduplication in
  Python.
- Root cleanup rule bookkeeping retains source_folder="/".
- Oldest-first selection uses parsed UTC ModTime and complete files.
- Reservation frees at least the exact calculated byte deficit.
- Reservation rechecks live local and remote state and can repeat up to 10 passes.
- Positive reserved uploads use reserved-bytes + 1 with --cutoff-mode CAUTIOUS.
- Per-remote reservation/trash/sleep/upload pipelines remain independent; there
  is no global reservation barrier.
- Post-upload cleanup, remote quota cleanup, trash cleanup, and final verification
  still run after a failed/partial upload pipeline.
- Drive, MEGA, and OneDrive backend-specific direct-delete mappings remain in the
  backend helper module.
- The production config values used by this package remain four threads in each
  configured category, GDrive/Mega/OneDrive, and 12G/12G/50G max_total_size.

Limitations
-----------
No destructive end-to-end run was performed against the user's real cloud
remotes for v0.0.18. The fake-rclone integration validates application flow and
state transitions but cannot reproduce provider APIs, throttling, trash/recycle
semantics, crypt backend behavior, or provider-specific rclone errors. A
controlled live run is still required for provider-specific production proof.
